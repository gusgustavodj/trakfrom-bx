# Security reporting

Report vulnerabilities privately. Do not include exploitable details, secrets,
real libraries, music or personal logs in an issue or Pull Request.

Reports in scope include privilege escalation, arbitrary command execution,
unintended disk writes or formatting, ownership bypass, VHDX safety bypass,
installer/uninstaller deletion issues and secret exposure.

If the repository Security tab offers **Report a vulnerability**, use that
private channel with a minimal synthetic reproduction and sanitized evidence.
Private reporting availability depends on GitHub repository capabilities; no
email or alternate private contact is designated. If the option is unavailable,
withhold sensitive details and open only a non-sensitive request asking the
maintainer to arrange private reporting. Never post the exploit there.

The maintainer reviews reports manually; there is no promised response SLA.
This pre-release does not promise maintenance of older versions.
